# Project notes

Read `PLAN.md` before making design decisions — it holds the product flow, the
recommendation engine design, and the phased build order.

## Versions that differ from common defaults

- **Next 16.** `middleware.ts` is now `proxy.ts`. Per the Next docs, proxy is
  for optimistic checks only — real auth checks belong in the page or route
  handler, which is where this project does them (`currentUser()`).
- **Prisma 7.** Requires a driver adapter (`@prisma/adapter-pg`); the client is
  generated as TypeScript into `src/generated/prisma` and is gitignored,
  regenerated by the `postinstall` script. Config lives in `prisma.config.ts`.
- **Tailwind 4.** Tokens are declared with `@theme inline` in `globals.css`,
  not in a `tailwind.config.js`.

## Conventions

- Vector columns are `Unsupported("vector(384)")`, so Prisma Client cannot read
  or write them. Use raw SQL, and build the literal only via
  `src/lib/vector.ts`.
- New embedding dimensions require a migration; `EMBEDDING_DIM` and the
  `vector(384)` columns must stay in agreement.
- The interest catalog is data (`src/data/interests.ts`). Editing a
  `description` changes its seed vector, so re-run `npm run db:seed`.
- No paid APIs. If a task seems to need one, check PLAN.md — there is usually a
  free path already chosen.

## Verifying work

`npm run typecheck && npm run lint && npm run build` should all pass. The
database work is verifiable: `psql` against `DATABASE_URL` and check that
vectors are non-null and that similarity queries return sensible neighbours.
